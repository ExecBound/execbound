# Integrations manifest

`manifest.json` is the source of truth for [`docs/INTEGRATIONS.md`](../docs/INTEGRATIONS.md): one entry per integration path with its placement (Execute, Gate, Monitor), its enforcement mode, its evidence state (research-only, fixture-tested, platform-validated), the versions that were tested, the test node ids or the trial record behind it, its recipe and its limits. `manifest.schema.json` is the shape. `tests/test_integrations_manifest.py` refuses a row that does not match the schema, a fixture-tested row whose tests this suite does not collect, a research-only row that claims a version or a mode, a recipe path that is not a file, unless it is a document the documentation site does not publish, and a commercial word in a row or on the page.

Every claim a row makes is checked against something that exists. Four of those checks read the project's own documents, not all of which are published, so they run only where those documents are: a platform-validated row's trial record has to exist and carry the interview fields, a landscape anchor has to be a heading in the project's survey of agent platforms, a recipe the documentation site does not publish has to exist, and the committed page has to be the manifest's current rendering. The page's tables are generated from the manifest and never edited by hand.

A row moves up only by evidence: a CI test promotes it to fixture-tested, a dated trial record carrying the interview fields promotes it to platform-validated. Vendor story exports and connector recipes live beside this file in their own directories (the Tines stories are under `tines/`).
